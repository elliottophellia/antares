# Researching a topic

## Plan before searching

Write the question down in one sentence. Then list what an answer would have
to contain. Searching without that list produces a pile of links and no
answer.

## Search in layers

1. **Orientation** — one broad search to learn the vocabulary of the field.
   Terms found here make the next searches much sharper.
2. **Primary sources** — documentation, the specification, the repository, the
   paper. Prefer these over anything summarising them.
3. **Recency check** — if the topic moves fast, add the year, and check dates
   on everything. A confident blog post from 2021 about an API is fiction now.

Use `web_search` to find candidates and `web_fetch` to read them. Reach for
`browser` when the page needs JavaScript, a login, or a form.

## Read against the question

For each source, note only what answers the question, and where it came from.
If two sources disagree, say so rather than picking the one you read last —
disagreement is a finding.

## Report

- The answer first, in a few sentences.
- Then the evidence, each claim next to its source.
- Then what remains uncertain, and what would settle it.

Never present a plausible-sounding synthesis as sourced fact. If something is
inference, label it.
